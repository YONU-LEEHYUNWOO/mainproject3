# **1. 문서 목적**

본 문서는 CAREMONITOR AI 케어비서 서비스 및 보호자 관리 서비스 구축을 위해

기능적·기술적·정책적 요구사항을 정의한다.

본 문서는 다음 조직이 동일 기준으로 개발·운영할 수 있도록 한다.

- 앱 개발팀(부모용/자식용)
- 서버/API 개발팀
- AI/모델링팀
- UX/UI 디자인팀
- 서비스 운영팀
- 데이터 분석팀

---

# **2. 용어 정의**

| 용어 | 설명 |
| --- | --- |
| 사용자(부모) | 케어 대상. 노인/장애인/유아 등 |
| 보호자(자식) | 사용자의 상태와 일정을 관리하는 가족/담당자 |
| 부모용 앱 | 사용자(부모)에게 제공되는 AI 케어비서 앱 |
| 자식용 앱 | 보호자에게 제공되는 부모 관리·모니터링 앱 |
| AI 케어 엔진 | 일정 안내·추천·생활 지원·안전 감지를 수행하는 AI |
| 무활동 감지 | 일정 시간 기기 활동이 없을 때 감지하는 기능 |
| 리포트 | 보호자에게 발송되는 사용자 케어 활동 요약 |
| 행동 반경 | 일정 기간 동안 사용자가 이동한 거리 및 패턴 |
| 패턴 모델 | 사용자의 반복적 행동을 분석하여 추론하는 AI 모델 |

# **11. 제약조건 (Constraints)**

| 항목 | 설명 |
| --- | --- |
| 부모-자식 양쪽 모두 가입 필수 | 자식 앱 없이는 부모 앱 일부 기능 제한 |
| 위치 정보 필수 | 실시간 케어 및 안전 감지를 위해 필요 |
| 고령층 UX 최적화 필요 | 버튼 기반 인터페이스 중심 |
| 실시간 알림 인프라 필요 | 무활동 감지·안전 알림 필수 |
| OS 백그라운드 정책 영향 | Android·iOS 별 정책 검토 필수 |
| 배터리·센싱 제약 | 저전력 모드에서는 감지 기능 일부 제한 |
